## אפיון המערכת

מערכת זו מהווה תשתית נתונים מקיפה (Relational Database) לניהול פלטפורמת מסחר אלקטרוני מקצה לקצה. המערכת מתוכננת לתמוך בנפחי נתונים גדולים ולנהל את כל שרשרת האספקה, משלב קליטת המוצר מהספק ועד לאספקתו ללקוח הקצה, תוך מעקב אחר מלאי, כוח אדם ופידבק צרכני.

### היחידות העסקיות והתהליכים המנוהלים במערכת:

**1. ניהול קטלוג, מלאי ושרשרת אספקה (Inventory & Supply Chain)**

* **מוצרים וקטגוריות:** ניהול עץ קטגוריות חכם וקישור כל מוצר לקטגוריה רלוונטית. לכל מוצר מוגדר מחיר וכמות מלאי עדכנית.
* **ספקים:** ניהול רשימת הספקים המספקים את הסחורה לחנות, כולל פרטי חברה ואנשי קשר.
* **מחסנים פיזיים:** המערכת מנהלת פריסה גיאוגרפית של מחסנים, כולל מעקב אחר קיבולת המחסן (Capacity) ושיוך כל מוצר פיזי למחסן שבו הוא מאוחסן בפועל.

**2. ניהול הזמנות ולוגיסטיקה (Order Management & Logistics)**

* **מחזור חיי ההזמנה:** מעקב מדויק אחר סטטוס ההזמנה (Pending, Processing, Shipped, Delivered, Cancelled) החל מרגע ביצועה על ידי הלקוח ועד להגעתה ליעד.
* **פירוט הזמנה (Order Items):** ניהול רזולוציית הפריטים בתוך כל הזמנה, תוך שמירה היסטורית של המחיר ליחידה (UnitPrice) בעת הקנייה וכמות הפריטים, למניעת עיוות נתונים במקרה של שינוי מחיר עתידי.
* **שילוח:** קישור כל הזמנה לחברת השילוח (Shipper) האחראית על הפצתה ללקוח.

**3. שיווק, מחירון ושימור לקוחות (Marketing & Customer Retention)**

* **מערך קופונים:** תשתית לניהול מבצעים הכוללת הפקת קוד קופון, הגדרת אחוז הנחה, וקביעת תאריך תפוגה (ExpiryDate). המערכת מאפשרת הזנת קופון בעת ביצוע הזמנה.
* **מערכת ביקורות (Reviews):** איסוף וניהול דירוגים (1 עד 5) וביקורות מילוליות מלקוחות עבור מוצרים שרכשו, לצורך הצגת דירוג אמינות המוצר בחנות.

**4. משאבי אנוש וניהול תפעולי (HR & Operations)**

* **עובדים:** ניהול מצבת כוח האדם של החברה. כל עובד מקושר לתפקיד מוגדר (Role), לתאריך תחילת העסקה, ולמחסן הפיזי אליו הוא משויך ובו הוא מתפעל את ההזמנות.
* **שיוך אחריות:** כל הזמנה מקושרת לעובד ספציפי (EmployeeID) האחראי על הליקוט והטיפול בה, לצורך בקרת איכות ומעקב תפוקות.

* **מסד נתונים:** PostgreSQL

# דוח שלב ה' - ממשק גרפי (Web GUI)

## הוראות הפעלה
הוראות מלאות: **[stage_5/RUN_INSTRUCTIONS.md](stage_5/RUN_INSTRUCTIONS.md)**. בקצרה (מתוך התיקייה `stage_5/app`):

1. התקנת תלויות: `npm install`
2. העתקת קובץ ההגדרות והזנת פרטי החיבור ל-Supabase של הפרויקט המשולב:
   `cp .env.example .env` ואז למלא ב-`.env` את פרטי ה-**Session pooler** (host, user `postgres.<ref>`, סיסמה).
3. הרצה: `npm run dev` — מריץ יחד את שרת ה-API ואת אפליקציית ה-React. פותחים בדפדפן את `http://localhost:3000`.
4. כניסה: `admin` / `admin` (ניתן לשינוי ב-`.env`).

## דרך העבודה והכלים
* **צד לקוח (Frontend):** React + TypeScript + Vite + Tailwind CSS, בעיצוב "NexusCommerce" (אותה שפה גרפית של אבטיפוס ה-UI).
* **צד שרת (Backend):** Node.js + Express עם הדרייבר `pg`. הדפדפן **לא** ניגש ישירות ל-PostgreSQL; ה-React קורא ל-API קטן (`/api/*`) וה-Express מדבר עם בסיס הנתונים. כך אפשר להריץ פונקציית **REF CURSOR**, לקרוא ל-**פרוצדורות** (CALL), ולהריץ את שאילתות שלב ב' כמות שהן, וגם הסיסמה של בסיס הנתונים נשארת בשרת בלבד.
* **ארכיטקטורה מבוססת אינטרוספקציה:** השרת קורא את הקטלוג של בסיס הנתונים (information_schema) ובונה אוטומטית את המטא-דאטה של כל הטבלאות (עמודות, מפתחות, מפתחות זרים). מסך ה-CRUD ב-React הוא **גנרי** ונבנה מהמטא-דאטה הזו, כך שהוא מסתגל לסכמה המשולבת האמיתית.

## עמידה בדרישות השלב
* **מסך כניסה** ➜ מסך לוגין שממנו נכנסים לכל מסכי המערכת.
* **CRUD לכל הטבלאות** ➜ מסך גנרי לכל הטבלאות (מקומיות + הלוגיסטיקה המרוחקת):
  * **שליפה (Read):** טבלה עם חיפוש. **לא מוצגים ערכי ID** — מפתחות זרים מוצגים כ**שמות** (למשל שם הקטגוריה במקום המספר) באמצעות תת-שאילתה מתואמת.
  * **הוספה (Create):** טופס עם **רשימות נפתחות של שמות** למפתחות זרים; ה-ID נוצר אוטומטית.
  * **עדכון (Update):** בוחרים שורה ➜ המערכת **טוענת את ערכי השדות הקיימים** ➜ עורכים ושומרים (לפי הדרישה "המשתמש ימלא את המפתח והמערכת תביא את יתר השדות").
  * **מחיקה (Delete):** עם אישור. הטבלאות המרוחקות הן לקריאה בלבד ומשתנות **בעקיפין** דרך הפרוצדורות של שלב ד'.
* **שאילתות ותתי-תוכניות** ➜ מסך "Queries & Procedures" המריץ את שאילתות שלב ב', מבטי שלב ג', ואת **2 הפונקציות + 2 הפרוצדורות** של שלב ד' (כולל הצגת פלט ה-NOTICE וטבלת ה-REF CURSOR).
* **השפעת פעולות/טריגרים:** הוספת פריט הזמנה מפעילה את הטריגר שמפחית מלאי וזורק חריגה אם אין מלאי מספיק — נראה ישירות במסך.
